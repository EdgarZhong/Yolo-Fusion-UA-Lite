# 双模态 YOLO-OBB 高分辨率极限微调实施手册

## 1. 背景与目标
本项目已完成基于权重迁移的深度调优（Tuned Phase），最佳模型（Epoch 154）在测试集上取得了优异的基准成绩。当前阶段的目标是通过**高分辨率微调（High-Res Fine-tuning）**策略，挖掘模型在小目标检测上的极限潜力。

**核心逻辑**：
尽管原始数据的有效像素宽度为 640，但将输入分辨率上采样至 **800**，可以使极微小目标（<8像素）在特征金字塔 P3 层占据更多的特征点，从而跨越检测阈值，显著提升召回率（Recall）。配合极低的学习率接续策略，在不破坏已有特征结构的前提下，实现模型精度的“压哨提升”。

## 2. 路径与文件规范

为防止覆盖已有成果，本次微调将在独立的实验命名空间下进行。

| 资产类型 | 路径/名称约定 | 说明 |
| :--- | :--- | :--- |
| **源模型权重** | `models/posttrain/FA-Concat_FPN-PAN_tuned/weights/best.pt` | **必须**使用 Tuned 阶段获得的最佳权重（Epoch 154）。 |
| **数据集配置** | `src/cfg/datasets/dual_obb_dronevehicle.yaml` | 保持不变。 |
| **训练执行脚本** | `src/trainning/final_polish_train.py` | 需新建专用脚本，用于覆盖特定的微调参数。 |
| **实验输出目录** | `models/posttrain/Final_Polish_800_FlipScale/` | 避免与原 Tuned 目录混淆。 |

## 3. 训练脚本开发 (`src/trainning/final_polish_train.py`)

开发人员需建立新的训练入口，核心逻辑是加载现有的最佳权重，并强制覆盖超参以进入“纯净微调”模式。

**关键逻辑要求**：
1.  **模型加载**：直接加载 `.pt` 文件而非 YAML 配置文件，确保继承所有结构参数。
2.  **分辨率重设**：强制指定 `imgsz=800`。
3.  **保存策略**：启用 `save_period=5`，确保存档中间权重，防止意外中断或过拟合回滚。

---

## 4. 关键超参设置表 (Hyperparameters)

请在脚本中严格硬编码以下参数。这些数值基于上一阶段收敛状态（Epoch 154, LR≈0.0024）计算得出，旨在实现平滑的接续训练。

### 基础训练配置
| 参数项 | 设定值 | 实施依据 |
| :--- | :--- | :--- |
| **model** | `.../FA-Concat_FPN-PAN_tuned/weights/best.pt` | 基于当前 SOTA 权重继续训练。 |
| **epochs** | `40` | 短周期微调。前 1-5 轮用于适应 BN 层统计值的变化，后续用于收敛。 |
| **imgsz** | `800` | **核心策略**。通过上采样放大微小目标，对抗特征层下采样带来的信息丢失。 |
| **batch** | `12` (或适量降低) | 800 分辨率显存占用较高，需根据硬件下调 Batch Size。 |
| **save_period** | `5` | 每 5 轮保存一次检查点，保留容错空间。 |

### 优化器与学习率策略
| 参数项 | 设定值 | 实施依据 |
| :--- | :--- | :--- |
| **optimizer** | `SGD` | 保持优化器一致性。 |
| **lr0** | `0.0025` | **接续学习率**。匹配源权重在 Epoch 154 时的学习率，避免梯度剧烈跳变。 |
| **lrf** | `0.05` | **快速衰减**。最终学习率约为 $0.000125$，确保模型沉淀到局部最优解。 |
| **warmup_epochs** | `0` | **关闭热身**。模型已成熟，直接进入微调状态。 |
| **cos_lr** | `True` | 使用余弦退火策略。 |

### 数据增强策略 (Cosmetic Finetuning)
**核心原则**：关闭所有产生“非真实样本”的增强（如马赛克、色彩变换），仅保留极微小的几何扰动以防止位置过拟合。

| 参数项 | 设定值 | 实施依据 |
| :--- | :--- | :--- |
| **mosaic** | `0.0` | **关闭**。消除拼接伪影，让模型适应完整的大图分布。 |
| **mixup** | `0.0` | **关闭**。 |
| **copy_paste** | `0.0` | **关闭**。 |
| **hsv_h/s/v** | `0.0` | **全关闭**。保护双模态物理特征，严禁引入色彩噪声。 |
| **degrees** | `0.0` | **关闭**。保护 OBB 角度回归精度。 |
| **fliplr** | `0.5` | **开启**。保留左右翻转，增加基础鲁棒性。 |
| **flipud** | `0.0` | **关闭**。视数据集分布而定，默认关闭以求稳。 |
| **translate** | `0.05` | **极微小**。仅保留 5% 的平移，防止模型过拟合于绝对坐标。 |
| **scale** | `0.1` | **极微小**。仅保留 10% 的尺度抖动，适应不同飞行高度，但不破坏 800px 的上采样红利。 |

## 5. 开发者实施核查清单 (Checklist)

在启动训练前，请确认：

1.  [ ] **显存预估**：确认 GPU 显存足以支撑 `imgsz=800` + `batch=12`。如不足，优先降低 Batch 至 8 或 4，**严禁降低 imgsz**。
2.  [ ] **源权重确认**：脚本指向的 `best.pt` 必须是 Tuned 阶段验证集 mAP 最高的权重。
3.  [ ] **学习率对齐**：确认 `lr0` 已设为 `0.0025`，而非默认的 `0.01`。
4.  [ ] **BN 层震荡预期**：训练启动后的前 3-5 个 Epoch，Loss 可能会短暂上升或 mAP 波动，这是 Batch Normalization 层在适应 800 分辨率分布，**属于正常现象，请勿中断**。

## 6. 验证与推理说明

训练完成后，在进行最终性能评估时，必须保持分辨率的一致性：

*   **注意**：必须显式指定 `imgsz=800`，否则 YOLO 可能会默认回退到模型训练时的配置或 640，导致性能下降。开启 `augment=True` (TTA) 可进一步推高最终得分。
